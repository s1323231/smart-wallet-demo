# イベント参加特典（動作確認済みデモ）

Googleログイン → ニックネーム入力 → 登録内容確認 → 参加登録 → テスト用1 JPYCと参加証NFTの受取確認、の流れです。
1ウォレットにつき1回だけ登録・配布できます。イベント名は固定です。
ニックネームは画面表示のみで、保存・送信しません。
NFTは参加登録の記録であり、実際の来場を証明するものではありません。

## 現在の配布先

`0x9920538a6CA1b2573bf616BaEd1eA55F70C444B0`（Ethereum Sepolia）

実際のGoogleログイン・参加登録・1 JPYCの受取・NFT No.1の所有を確認済みです。
アプリの配布先は `.env.local` の `NEXT_PUBLIC_EVENT_REWARDS_ADDRESS` に設定しています。
自分のパソコンでこのデモを使うために、新しい配布プログラムを設置する必要はありません。
別の参加者に配る前は、配布用JPYCの残高を確認して補充してください。

## 配布の仕組み

`contracts/EventRewards.sol` はERC-721の参加証であり、JPYCの配布元です。
`register()` を呼んだウォレット自身に1 JPYCを送り、NFTを1枚発行し、登録日時を記録します。
これらは同じトランザクションで実行するため、JPYC不足や送金失敗時は登録とNFTも取り消されます。
ウォレット別の `certificateOf` により二重配布を防ぎます。
NFTの名前・画像・データは固定で、コントラクト内に保存されます。
NFTは通常のERC-721として移転できます。登録完了画面は発行時の配布実績を表示します。
現在の残高・NFT所有状況は、JPYC欄とNFTコレクションで確認します。

## JPYCの補充

公式Sepoliaテスト用JPYCは `0xE7C3D8C9a439feDe00D2600032D5dB0Be71C3c29` です。
アプリ内で取得したJPYCを、ERC-20送金画面から上記の配布先へ送れます。
参加者1人につき1 JPYC必要です。参加者が個別にFaucetを使う必要はありません。
このデモには余ったJPYCの引出機能がないため、必要な分を少量ずつ補充します。

## 結果不明時の確認

参加登録の処理状態は、イベント・ウォレット別にIndexedDB `event-registrations-sepolia` へ保存します。
別タブの予約もreadwriteトランザクションで排他します。
処理中・結果不明の間は再送せず、「受取状況を確認（送信しません）」で照会します。
登録記録、JPYCの送金ログ、NFTの発行、登録イベントを確認した後に完了画面を表示します。
送信後の応答が失われた場合も、配布を同時に確定するコントラクトの登録記録から復旧できます。
署名・秘密鍵・ニックネームは保存しません。
送信前の中止やチェーン上の失敗が確認できた場合だけ、明示的な再登録を許可します。
別ブラウザや保存データ削除ではブラウザの排他を共有しません。結果不明時は削除や再送をしないでください。

## 主催者向け：新規設置が必要な場合だけ

現在のデモの利用には不要です。新しく別の配布先を準備する場合に使います。

### アプリ内Smart Accountから設置

主催者 `0xF3B45d905b159C17baC29A9Bb8F2a04c731218d8` でログインし、JPYC欄の下の「主催者用：配布プログラムの設置」を開きます。
この表示制限は秘密の認証機構ではなく、設置用のプログラムは公開されています。

1. 「設置条件・スポンサーを事前確認（送信しません）」でSepolia接続、共通設置用コード、設置シミュレーション、スポンサーとガス見積もりを確認します。
2. 「設置内容を確認する」でアカウント・ネットワーク・設置予定アドレス・スポンサー・見積もりを確認します。キャンセルでは送信しません。
3. 最終確認ボタンで初めて署名・送信を行います。スポンサーが確認できなければ送信せず、自己負担送信への自動切り替えはしません。
4. 確定後は設置先のコード全体とJPYCを照合します。結果不明時は「設置状況を確認（送信しません）」を使います。
5. 新しい配布先設定・再起動・JPYC補充は別途行います。

共通設置先は `0x4e59b44847b379578588920cA78FbF26c0B4956C` です。
[deterministic-deployment-proxy](https://github.com/Arachnid/deterministic-deployment-proxy) のコードと照合します。
主催者・イベント識別子v1・固定プログラムからCREATE2で設置先を決めます。
同じプログラムを再操作しても別の設置先は作りません。
処理記録はIndexedDB `event-deployments-sepolia` に保存し、署名や秘密鍵は保存しません。
固定の設置先に一致するコードがあれば、ハッシュを取得できなかった場合も照会で復旧できます。

### 秘密鍵を使うスクリプト（任意）

Sepolia専用の主催者ウォレットにテストETHを用意し、`.env.local` に既存のAPI設定と `EVENT_DEPLOYER_PRIVATE_KEY` を設定します。
秘密鍵に `NEXT_PUBLIC_` を付けず、公開・コミットしないでください。
`npm run event:compile`・`npm run event:test` 後、`npm run event:deploy` で設置します。
表示されたアドレスを配布先に設定し、必要なJPYCを補充します。配置後の配布に秘密鍵は不要です。

## 検証と公開

Solidity変更後は `npm run event:artifact` でブラウザ用の公開バイトコードを生成し、
`node scripts/generate-event-deployment.mjs --check` でソースとの一致を確認します。
コンパイルはoptimizer runs=200、EVM Shanghaiを使用します。
`npm run event:test` は同時受取、在庫不足時の全取消、二重登録拒否、スポンサー拒否、保存と復旧、設置確認を検証します。
型チェック・変更ファイルのLintも行います。

他の人に使ってもらう前は、JPYCを補充し、別のGoogleアカウントで受取を確認します。
スマートフォンから使うにはアプリを公開し、Web3Authへ公開URLを登録して、そのURLのQRコードを作ります。
localhostは来場者のスマートフォンから利用できません。
本物のお金・商品との交換、店舗決済、厳密な来場確認は対象外です。
